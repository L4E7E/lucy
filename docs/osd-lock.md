# OSD와 잠금화면

## 상태바 확장

알림은 가운데 시계 바의 기존 `wl_surface`에서 카드로 확장된다. 펼친 알림에는
시계나 내부 카드 테두리가 없다. OSD는 같은 표면을 사용하되 높이 34px를 유지하고
좌우로만 확장한다. 모든 OSD 아이콘은 흰색이다. 게이지 값은 100ms 보간하며,
연속 입력은 현재 표시 위치에서 이어진다. 새 OSD나 종류 변경 시 이전 값은
이어받지 않는다. 변화가 끝나면 추가 프레임 요청을 멈춘다. 알림 표시 중 OSD가 들어오면
잠시 OSD를 표시한 뒤 아직 유효한 알림으로 돌아간다.
제어센터·알림센터 확장은 360ms, 알림 팝업 확장은 기존 480ms의 단조 감쇠 곡선을 사용한다. 세부 화면 전환은 300ms로, 진입할 때 왼쪽으로 밀리고 뒤로 갈 때 오른쪽으로 밀린다. 화면끼리 투명도를 섞지 않으며 글래스 배경과 상태바는 고정한다. 초반에 최종 크기로 튀어 올라 멈추는 곡선은 사용하지 않는다. OSD·스크롤·트레이의 기존 애니메이션 시간은 유지한다.
너비는 기본 시계 바보다 60px 넓게(최소 236px), 값 글씨는 16px로 표시한다. 키보드 백라이트는 퍼센트 대신 `꺼짐 / 1단계 / 2단계 / 3단계`처럼 장치의 실제 단계로 표시한다.

알림센터를 펼치면 58px 시계와 그 아래 18px 오늘 날짜가 달력 위에 배치된다. 시계의 별도 배경·테두리는 없다. 달력은 기준 배치보다 54px 아래로 이동하고, 접힌 상태바의 날짜 표시는 유지한다. 트레이 너비를 변경한 뒤 제어센터를 닫을 때는 열기 당시 너비가 아니라 현재 상태바 너비로 복귀한다.

알림센터의 ‘알림’과 세부 설정 제목은 시스템 글꼴의 20px Bold를 사용한다. 제어센터 토글의 아이콘과 제목은 8px 간격을 두고, 장치 선택 목록과 볼륨 게이지 사이에는 16px를 확보한다. 런처는 600×486px로, 네 번째 행의 아이콘이 절반 보이도록 자른다.

알림센터의 개별 카드와 팝업 오른쪽 위에 수신 시각을 표시한다. 1시간 미만은 로컬 `HH:MM`, 이후는 `N시간 전`, 24시간 이후는 `N일 전`이며 기존 분 단위 시계 갱신으로 함께 업데이트한다. 새 알림과 교체 알림의 수신 시각을 기록하고 기존 런타임 기록에도 보존한다. 시각이 없거나 잘못된 과거 알림은 추정하거나 대체 문구를 넣지 않고 아무것도 표시하지 않는다. 시간·활성 표시·마우스 오버 삭제 버튼은 서로 겹치지 않게 배치한다.

알림 제목·본문·시간은 시스템 글꼴과 기존 크기를 유지한다. 알림을 그리는 동안만 힌팅을 끄고, 벡터 글자 외곽선을 물리 해상도의 4배로 샘플링한 뒤 면적 평균으로 축소한다. 최종 물리 크기의 A8 마스크만 보관하며 본문·제목은 최대 48개/2MiB, 짧은 시간 표시는 최대 32개로 제한한다. 스크롤 중 마스크를 재사용하고 물리 픽셀에 정렬한다. 비밀번호는 캐시하지 않으며 컬러 이모지는 Pango의 기본 렌더러를 유지한다. 화면 전체 해상도·시스템 글꼴 설정·블러·애니메이션은 바꾸지 않는다.

최종 EGL 합성의 부동소수점 계산·UV 보간·샘플러는 `highp`를 명시한다. 정밀도 매크로에 의존한 `mediump` 경로는 큰 물리 버퍼의 텍스처 좌표를 반올림해, 원본에서 부드럽던 알림 글자와 잠금화면 시계에 다시 계단현상을 만들 수 있다. 고정밀 셰이더를 지원하지 않는 GPU는 기존 SHM 대체 경로를 사용한다. 잠금화면 시계는 가로 폭과 아래쪽 위치를 유지하고 세로 윤곽만 14% 늘린 뒤 글래스 재질과 안티앨리어싱을 계산한다. 날짜와 알림센터 시계의 디자인은 바꾸지 않는다.

아래 검사는 입력을 받지 않는 미리보기에서 잠금화면·펼친 알림센터 합성 경로의 GPU 픽셀을 원본과 비교한다. 실제 잠금이나 PAM 인증을 요청하지 않고, 읽어 온 픽셀은 테스트 메모리에서만 사용한다. 일반 실행 파일에는 GPU 읽기 검사와 버퍼가 포함되지 않는다.

```sh
LUCY_UI_TEST_NO_INPUT=1 cargo test --release --locked --offline --bin lucy-shell \
  lock::tests::gpu_preserves_lock_and_joined_notification_text_coverage -- --ignored --nocapture
```

런처 휠 스크롤은 즉시 속도를 얻고 부드럽게 감속하는 전용 관성 곡선을 사용한다. 연속 입력의 속도는 이어지고, 양끝에서는 튕김 없이 정확히 멈춘다. 터치패드·스크롤바 드래그는 직접 입력을 유지하며 다른 목록의 곡선·거리 배율은 바꾸지 않는다. 기존 Wayland 프레임 콜백을 사용하고 스크롤 화면을 추가로 교차 페이드하지 않는다.

```sh
lucy-shell osd volume up        # 출력 볼륨 +5%
lucy-shell osd volume down
lucy-shell osd volume mute
lucy-shell osd microphone mute
lucy-shell osd brightness up
lucy-shell osd brightness down
lucy-shell osd keyboard up      # 실제 장치 기준 한 단계 (ASUS: 꺼짐/1단계/2단계/3단계)
lucy-shell osd keyboard down
lucy-shell osd keyboard show    # 밝기를 바꾸지 않고 OSD만 표시
lucy-shell osd profile cycle    # 절전 → 균형 → 성능 (지원되는 모드만)
```

장치 변경은 별도 작업 스레드에서 처리하며 키 반복 요청은 합친다. 상태바가
꺼져 있어도 명령의 장치 제어는 동작한다. 외부에서 전원 모드가 바뀌어도 OSD를 표시한다.
ASUS Fn+F2/F3는 커널이 직접 처리하여 일반 XF86 키나 D-Bus 신호가 나오지 않을 수 있다.
`brightness_hw_changed`의 `POLLPRI` 이벤트를 직접 감시하고 그 이벤트 값을 표시한다.
일반 `brightness` 파일이나 UPower에는 이전 값이 남을 수 있어 Fn 키 이벤트에 사용하지 않는다.
상한을 넘는 4단계 요청은 최대 밝기로, 하한에서 발생하는 `ENODATA`는 0으로 처리한다.
UPower와 ASUS D-Bus 신호 감시는 프로그램에서 변경한 밝기를 위한 보조 경로로 유지한다.

ASUS Fn+F5 전원 모드 OSD는 `/sys/firmware/acpi/platform_profile` 커널 알림을 직접 받고, `asus-wmi`의 장치별 `profile`에서 실제 모드를 읽는다. 여러 드라이버의 모드가 다른 경우 전역 값은 `custom`이 될 수 있으므로 표시 값으로 사용하지 않는다. 배터리·충전 상한·예약 설정을 전부 다시 읽는 작업은 표시 이후 별도로 진행한다. 전체 조회 결과가 늦게 도착해도 이미 표시한 OSD를 다시 띄우지 않는다. 하드웨어 알림을 지원하지 않는 장치에서는 기존 전원 서비스 감시를 사용한다.

커널 경로 참고: [ASUS WMI 키 처리](https://github.com/torvalds/linux/blob/master/drivers/platform/x86/asus-wmi.c), [LED 하드웨어 알림](https://github.com/torvalds/linux/blob/master/drivers/leds/led-class.c), [전원 프로필 알림](https://github.com/torvalds/linux/blob/master/drivers/acpi/platform_profile.c).
Niri 키 설정 예시는 `integration/niri.kdl`에 있다.

## 세션 메뉴 배경

종료·재부팅·잠금 등 다섯 버튼을 표시하는 세션 메뉴는 반투명 한 픽셀을
출력별 화면 크기로 확장한다. `lucy-session-backdrop`에 `blur true`,
`xray false`를 적용하여 배경화면뿐 아니라 실제 열린 창까지 Niri가 블러
처리한다. 이 메뉴에서는 화면 캡처·CPU 블러·출력별 이미지 버퍼를 만들지
않는다. 수정된 다중 GPU 블러를 포함하는 Niri가 필요하다.
아래의 보안 잠금 화면은 별도 경로이며, 불투명 표면과 인증 절차를 유지한다.

## 실제 세션 잠금

```sh
lucy-shell lock                 # 실제 잠금; Enter로 시스템 비밀번호 인증
lucy-shell lock --daemonize     # compositor의 Locked 확인 후 호출자에게 반환
lucy-shell lock --preview       # 잠금이 아닌 미리보기; Esc로 종료
```

잠금은 별도 프로세스에서 `ext-session-lock-v1`과 시스템의 `/etc/pam.d/swaylock`
PAM 정책을 사용한다. 일반 레이어 팝업으로 잠금을 흉내 내지 않는다. 모든 출력과
추가 연결된 출력에 불투명 잠금 표면을 만들며, 인증 성공 뒤에만 잠금을 해제한다.
실패·Escape·프로세스 오류로는 해제하지 않는다. 셸 재시작도 잠금 프로세스를 종료하지 않는다.

잠금 시계는 시스템 글꼴을 사용하며 96px로 표시한다. 숫자만 물리 해상도의 2~4배로 계산한 뒤 마스크·굴절·반사광을 함께 축소한다. 150% 배율에서는 4배를 사용한다. 부분 커버리지를 반영한 유클리드 거리와 부드러운 법선은 배경 굴절에만 사용한다. 날카로운 반사선은 글꼴의 실제 베지어 곡선에 그려 거리장 픽셀 노이즈가 반사광에 나타나지 않게 한다. 넓은 회백색 입체 음영을 없애고, 배경이 비치는 몸체와 얇은 곡선 반사로 유리 질감을 만든다. Wayland의 선호 배율을 사용하고, 지원되는 GPU에서는 고정밀 텍스처 좌표를 사용한다. 세로 그라데이션이나 검은 외곽선은 사용하지 않는다. 결과는 출력별로 캐시해 비밀번호 입력 시 재계산하지 않고, 이전 분의 이미지는 교체한다(최대 4개). 날짜·인증 흐름은 변경하지 않는다.

빈 비밀번호 입력창의 안내 글자는 21px이며, 순백색 빛 한 줄기가 왼쪽에서 오른쪽으로만 1.4초 동안 이동한 뒤 0.55초 쉰다. 밝은 중심부를 넓히고, 빛이 오른쪽으로 완전히 빠져나간 상태에서 쉰 뒤 왼쪽에서 다시 들어오게 하여 양끝에 하이라이트가 동시에 생기지 않는다. 실제 글자 폭에 맞춘 고정 마스크와 GPU 셰이더만 사용하며, 시계 갱신에도 위상을 유지한다. Wayland 프레임 콜백에 맞춰 표시하고, 매 프레임 전체 화면을 Cairo로 다시 그리거나 텍스처를 다시 올리지 않는다. 입력·인증 중에는 효과와 추가 프레임 요청을 멈추고, 입력을 비우면 다시 시작한다. GPU를 사용할 수 없으면 정적인 안내 글자로 대체한다. 별도 캡처는 추가하지 않는다.

Niri의 창 블러는 세션 잠금 표면에 적용되지 않으므로 잠금 직전 이미지를 메모리에서만
캡처하여 한 번 블러 처리한다. GPU에서는 진입 시 380ms 동안 블러가 강해지고,
인증 성공 후 300ms 동안 풀린다. 해제 연출이 끝날 때까지 실제 세션 잠금은 유지한다.
애니메이션마다 다시 캡처하거나 화면을 래스터화하지 않는다.
캡처에 실패하면 불투명 단색 배경을 사용한다. 비밀번호는
로그·파일·IPC로 보내지 않으며, 제한된 `mlock` 버퍼에서 관리하고 사용 후 지운다.

`integration/lucy-lock.service`와 `integration/lucy-idle.service`를 사용자 서비스 디렉터리에 설치하고 기존 swayidle
시작 항목을 교체하면 logind 잠금·절전 직전 잠금을 연결할 수 있다. 준비 실패에 대비한
Swaylock과 기존 PAM 설정은 삭제하지 않는다. 잠금 클라이언트가 비정상 종료되어
화면이 잠긴 채 남으면 다른 TTY에서 같은 사용자로 `swaylock`을 실행하여 복구할 수 있다.

## 검증 범위

일반 `cargo test --release --locked`는 실제 계정 인증이나 화면 잠금을 하지 않는다.
프로토콜 테스트는 `/tmp/lucy-osd-lock.*` 아래의 격리된 Niri 소켓에서만 허용된다.
테스트용 인증기는 `#[cfg(test)]`에만 존재하며 배포 실행 파일에는 포함되지 않는다.
실제 비밀번호 인증과 절전·복귀는 사용자가 별도로 확인해야 한다.
